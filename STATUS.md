## What works now

- Public repository: https://github.com/cardovaeric/aws-calc-axi (default branch `main`).
  Agents can install the guide with `npx skills add cardovaeric/aws-calc-axi --skill aws-calc-axi`;
  the CLI itself installs from a clone with `npm install && npm link`.
- TypeScript Node project with a real binary (`bin/aws-calc-axi.js`), native TS execution,
  `npm run typecheck`, `npm run lint`, `npm test`, `npm run e2e`, `npm run ledger`.
- Fast version path: `--version`, `-v`, `-V` answer before the CLI graph loads.
- Catalog: manifest, region map, locations, exact region-aware rule. Parity with the live UI:
  181 us-east-1, 160 us-east-2 (`e2e/catalog.test.ts`).
- Definition and pricing clients: disk cache, retry/backoff, offline mode, region-less price
  merging (`Any` bucket), gzip via fetch. PLC_2.0 column-form data (metadata, selector
  aggregations, index price trees) is fetched and cached the same way.
- Engine: inputs (`numericInput`, `dropdown`, `fileSize`, `frequency`, `durationInput`,
  `percentInput`, `checkbox`, `throughput`, `utilization`, `dataTransferV2`, `columnFormIPM`,
  display-only text), `displayIf`,
  `singlePricePoint`, `tieredPricing`/`tieredPricingMath`, `pricingComboV2`, `replace`,
  `concatenate`, `basicMaths`, `maxMin`, `rounding`, `variable`, `priceDisplay`, `[ZERO_COST]`,
  config summaries, subtotals. Unknown subtypes fail closed with the component path.
- Data transfer pricing is native: per-destination tier groups, the region-wide most-common
  group, destination overrides, the intra-region double charge, and the live
  `DT <type>: <region> (<n> <unit>)` summary. Unselected rows and unknown destinations fail
  closed.
- `columnFormIPM` is native for the PLC_2.0 row set: `textInput`/`autoSuggest`/`dropDown`
  selectors, selector-pattern price extraction (On-Demand, Reserved, `$overridePriceKeyWith`),
  hidden dependent selectors, a 100% utilization row, `disableCalculation` rate components, one
  price set, hourly or monthly model, `calculationId` targets exposed to the maths section, live
  save format and summary, and `displayIf`-gated prefetch (only visible cards fetch PLC_2.0 data).
  A component holds exactly one row, like the live calculator: its editor recompute reads
  `value[0]` and a second configuration is a second service (`analysis/FINDINGS.md` section 13).
  Database Savings Plans, aggregation remaps, sub-components, and tiered PLC_2.0 patterns still
  fail closed (`docs/DECISIONS.md` D-024 and D-027).
- `throughput` inputs are native (kbps/mbps/gbps with binary conversion to MBps), which unlocks
  gp3 volume and RDS storage inputs.
- `utilization` inputs are native (percentage, hours, or minutes per day, week, or month to hours
  a month, with the live rounding), which unlocks AWS PCS and Elemental MediaConnect end to end
  and unblocks the Deadline Cloud and Direct Connect rows down to their column-form gaps. The
  live `pricingComboV2` missing-meter zero and `replace` no-match passthrough were needed for
  MediaConnect. See `analysis/FINDINGS.md` section 15 and D-028.
- A real client estimate was built and published for BINUS SCHOOL eDesk:
  `https://calculator.aws/#/estimate?id=80c119fedeab83ca5fa8a7da79dad61d77c93374`
  (Production 1,429.13, Non-production 762.50, total 2,191.63/month). It was generated by
  publishing the component payload, clicking "Update estimate", and sharing the recomputed
  estimate. See FINDINGS section 12.
- Selector parents emit `subServices[]`; user groups nest with `Name-uuid` ids; support plans
  compute from the published tier table.
- Publisher: `saveAs`, public URL, saved-key retrieval, daily link budget, link reuse from a
  receipt when the spec hash matches, recompute probe links for the live UI oracle, and an
  editor-recompute oracle (`--oracle-editor`) for components the read-only probe drops.
- Verifier: opens the public URL in a named agent-browser session, waits for the estimate name,
  reads the banner, totals, service/group rows, group tree, and support row; diffs to the cent.
  The editor mode clicks "Update estimate" and reads the same DOM.
- CLI: home, `services`, `schema`, `pricing`, `estimate init`, `cost`, `apply`, `publish`
  (`--oracle`, `--oracle-editor`, `--receipt`, link reuse), `verify`, `doctor`, `update`.

## Open failures and blockers

- None blocking.
- Publish budget: the shared counter is far past the 25/day default because the P0 conformance
  run and these receipts share it (see `docs/DECISIONS.md` D-017 and D-025). The utilization
  receipts used four links with a per-process override; the default cap is unchanged.
- The read-only share page drops `dataTransferV2` when it recomputes a foreign-source estimate
  (it renders 0). The editor recompute is correct, so data transfer receipts use
  `--oracle-editor`. Evidence in `analysis/FINDINGS.md` section 9.
- Fail-closed gaps (adapter tasks, not silent zeros): bespoke EC2/Windows/RDS math
  (`ec2PriceDisplay`, `ec2Variable`, `snapShotMaths`, `workloadInstanceMath`), pricing
  `sets`-based instance data, and the remaining `columnFormIPM` surface (Database Savings Plans,
  sub-components, reserved/upfront totals, `remap.constant`, `utilization-selector`) listed in
  `docs/DECISIONS.md` D-020, D-021, D-024, and D-030.
- `percentInput` saves the entered percent, which the live editor rehydrates by dividing by 100
  again; saving the fraction made a rehydrated 100% read as 1% (the Keyspaces 25.69 vs 25.63
  oracle). D-026 has the bundle evidence.
- P1 is 11 rows, all engine gaps rather than tracker noise: five selectors name their children
  (Amazon Chime SDK `remap.constant`, Amazon EMR and Amazon WorkSpaces `utilization-selector`,
  Amazon Translate `remap.keyValue-primary`, AWS Mainframe Modernization `remap.constant`), plus
  AWS Directory Service (`remap.constant`) and five partial on `additional-pricing-data`
  (DocumentDB, Keyspaces, Neptune, Timestream, DMS). Evidence: `analysis/FINDINGS.md` sections 15
  and 16, D-028 to D-030.
- The `remap.keyValue` direction is native since `bf27e34` (forward on aggregation rows and price
  records, reverse on meter tokens and the index path). What is still missing is resolving the
  **primary** selector through the remapped option tree, which is
  `realTimeDocumentTranslation` alone: its default `Basic` is the price token while every option
  and aggregation row holds `Basic - Text, HTML`. The tracker blocks it with
  `remap.keyValue-primary`, the rule that replaced the retired `remap.keyValue-direction` and
  `regex-remap` rules, so no row carries a stale fail-closed label.
- Two clean rows still cannot evaluate their defaults, both in files this tracker does not own:
  `realTimeDocumentTranslation` (primary remap token, above) and `amazonLookoutForEquipment`,
  whose `fileSize` `defaultOption.frequency` ("month") is not in `dropDownFrequency`, so
  `src/engine/inputs.ts` rejects a default the live form accepts.
- Deadline Cloud and Direct Connect are clean now that `utilization` is native. Deadline Cloud
  evaluates (its price-set labels resolve through the dependent-selector work); Direct Connect
  needed the live region gate (`Array.isArray(availableLocation) && !includes()`) and the
  `Location` / `From Location` region injection on the index path (`docs/DECISIONS.md` D-030).
- Six services reference meters that are absent from their regional price file (Personalize,
  Transcribe, ACM, MediaTailor, Firewall Manager, IoT SiteWise). The engine fails closed
  instead of publishing a zero. The same `missing-price` verdict now covers 28 us-east-1 and 67
  us-east-2 rows, which also makes the AI model rows visible. For `ai21` (and `amazon`,
  `workload1`) the meter token exists in the `bedrockfoundationmodels` file while the component
  reads `bedrock`, so the meter lookup, not the data, is the gap. Those rows are left alone:
  they need per-service analysis, and relabelling them is not a tracker-only change.
